## 0. 变更控制（三位一体规则）

任何影响玩法数值/规则的改动，必须**同一次提交**里三件事都发生：

1. **代码**：`main/dungeon_model.c`（或 UI 层）改动；新旋钮用 `#ifndef TUN_*` 包裹（autotune 可覆盖）。
2. **门**：对应验收门覆盖新行为——单元测试钉最小场景，balance_sim 钉弧线，benchmark 钉分布。必要时新增门。
3. **文档**：本文对应章节 + §9 参数总表行（值、所属系统、编码的设计意图、所属版本弧线）。

弧线级改动（难度曲线、成长节奏、经济循环形状）还必须：跑 benchmark 双 salt 对比分布、
在 §10 记一行（版本号、动机、曲线前后、放开了哪些门、为什么可以放开）。

**美术/素材改动额外规则**：所有 preview 必须 RGBA ≥5% 透明 + <20% 白不透明（`audit_assets.py`
门禁强制）。`.spr4` 动画包帧边界不得有白不透明调色板条目。源目录 `.png` 必须是真 PNG。
**代码改的人必须查素材，管素材的人必须查代码——交接处放门，不放信任。**

> 教训（DEVLOG 2026-09-06）：balance_sim 的"迷宫消耗 ≤30"门是 v10 时代"首通 60-100 跑"
> 弧线的化石，v12 把弧线压缩 2.5 倍时只放宽了部分门——**每个门都必须标注它编码的设计意图
> 和所属弧线版本，否则弧线改了，门变成地雷。** 这就是 §8 门意图表和本节存在的原因。


环的核心闭环（放置游戏的主循环）：

**探索迷宫 (§5) → 遭遇怪物 → 战斗 (§2×§7) → 掉落/金币 → 培养消费 (§4) → 数值变强 (§3)
→ 下次战斗更优势 → 更深层数 (§5) → 更强怪物与更高收入 → 回程保命 (§5.3) → 死亡清金币但保培养
→ 周目/转生 (§4.2, §5.1) → 弧线推进**

每个上游系统都是下游的输入，每条箭头都有对应的验收门。任何一个箭头的参数改动，
都会传导到环的远端——所以 §8 的长线门（150 跑）和分布门（benchmark）永远和局部单测同时看。

## 2. 战斗体系

### 2.1 基础公式（单一来源原则）

**伤害（怪→玩家）——`blob_hit()`，全游戏唯一一份每次伤害的数学：**

```
taken = eatk² / (eatk + geff + 1)          （Blob 曲线：平滑、非零、无悬崖）
geff  = guard ≤ 20 ? guard : 20 + (guard-20)/2     （守备软上限，§2.5 v12.2）
taken ≥ 1                                   （压力下限：永不归零）
taken = 1 + (taken-1) × EN_DMG/10           （全局伤害刻度，EN_DMG=0.8）
taken = taken × act.mult10/10               （行动倍率，§7.2）
taken = taken × 姿态减伤                     （GRD 重击 0.4 / GRD 常规 0.9 / EVA 闪避 30%）
taken ≥ 1                                    （落地不归零；干净闪避除外）
最后：护盾池吸收 → 诅咒/吸血挂账 → 扣血
```

> **单一来源原则（v12.2 教训）**：AI 判读（§6.1）与真实受击必须共用同一函数。
> 曾经 AI 读原始攻击力、现实走 Blob 链，感知是现实的 5 倍 → 满血烟遁。
> 任何新的伤害用途（UI 预估、离线结算）一律调 `blob_hit()`，禁止重写公式。

**玩家力量——`pow_of()`（乘区顺序，自上而下）：**

```
pow = 3 + explore_lv + job_lv + job_lv×pow_grow/4 + 武器实际值 + bless_atk
    × (100 + 3×圣所FOR)%        （圣所乘区）
    × (100 + 2×转生等级)%        （转生乘区）
    × m_pow10/100               （职业 M 轴乘区，§2.3）
    × codex 里程碑               （每 4 条 +4%，§4.1）
    × (空精力 ×0.7)              （精力惩罚，放置节奏阀门）
```

**守备——`guard_of()`**：`护甲实际值 + bless_def + 圣所DEF + job_lv×guard_grow/4`，最后 ×m_grd10/100。

**生命上限——`max_hp_of()`**：`26 + explore_lv×4 + job_lv×hp_grow`，依次 ×圣所VIT ×转生 ×m_hp10 ×codex，受伤 -20%。

### 2.2 乘区清单（改任何一处都要过 §3 军备竞赛）

| 乘区 | 值域 | 属于 | 门 |
|---|---|---|---|
| 职业 M 轴 (pow/hp/grd) | 70-130 | 身份（§2.3） | benchmark B |
| 圣所 FOR/VIT/DEF | 每级 +3/+5%，lv≤5 | 培养经济（§4.2） | balance_sim |
| 转生 | 每级 +2%，需要 ng | 周目弧线（§5.1） | prestige_loop 门 |
| codex 里程碑 | 每 4 条 +4% | 收集（§4.1） | G5c |
| 祝福 atk/def | ≤8（+16） | 单跑内成长 | G6 |
| 姿态 dealt/taken | §2.5 | 回合策略 | C 张力门 |

### 2.3 职业（身份=差异，不是数值皮肤）

| 职业 | AI 性格 | 技能1/2 | 解锁lv | M_pow | M_hp | M_grd | 本源词缀 | ULT | 主姿态 |
|---|---|---|---|---|---|---|---|---|---|
| 骑士 | CHARGE 冲锋 | 盾击/嘲讽 | 1 | 100 | 120 | 130 | GUARD | SK_CASTLE | GRD |
| 黑魔 | SNIPER 狙击 | 火/冰 | 1 | 120 | 85 | 70 | SLAYER | SK_METEOR | ATK |
| 白魔 | MEDIC 治疗 | 治愈/圣盾 | 6 | 70 | 110 | 105 | LEECH | SK_SANCTUARY | GRD |
| 盗贼 | BACKSTAB 背刺 | 毒刃/烟遁 | 16 | 110 | 90 | 85 | GREED | SK_JACKPOT | EVA |
| 暗骑 | EXECUTE 处决 | 吸血/末日 | 41 | 110 | 95 | 90 | VENOM | SK_ECLIPSE | ATK |

设计意图：M 轴跨度 70-130，**差异即身份**（骑士是墙、黑魔是炮、白魔是奶、盗贼赌、暗骑斩杀）；
benchmark B 门强制新档深度极差 ≥3 层。主/副双职槽 + auto_job 自动换职（§6.3）。

### 2.4 回合设计（`dungeon_round_ex` 阶段顺序）

```
1. round_ct++；姿态重算（§6.2）；enemy_fury 递减（战争怒吼时钟）
2. 敌方 DOT 结算（毒：3 点/跳，不带职业成长）
3. 飞行怪先手射击（EACT_FIRST；受 enemy_slow 每隔轮限制）
4. 进化 ULT：round 3 一次性爆发（idle 戏剧拍点；ULT 表见 §2.3）
5. 玩家自动攻击（按主职性格；EVA 整段跳过=结构性反乌龟）
   职业内建反应：白魔 <60% 自动治愈 / 黑魔 ≥2 怪自动火球 / 骑士前 2 轮盾击 /
   盗贼第 1 轮背刺（×1.5）/ 暗骑多怪或低血吸血
6. 技能 CD 递减（EVA 再减一跳：滑步加速技能周转）
7. 敌方主阶段（EACT 隐藏摇奖，§7.2；slow 每隔轮跳过）
8. 白魔恢复姿态再生（TUN_WHITE_REGEN）
```

马拉松保护：GRD 预计击杀 >10 轮 → 强制 ATK（防"架盾刮痧"拖节奏）；
round>100 强制 ATK（一切乌龟战必须在 200 轮硬上限前结束）。

### 2.5 姿态（回合策略层，v12 V2 战斗）

| 姿态 | dealt | taken | 特性 | 旋钮 |
|---|---|---|---|---|
| ATK 压制 | ×1.3 | ×1.0 | 无 | ST_ATK_DEALT 13 |
| GRD 架盾 | ×0.4 | ×0.9 | 重击 ×0.4 格挡 | ST_GRD_* |
| EVA 滑步 | ×0 | 闪避 30% | 重击必闪；CD 加速 | EVADE_DODGE 30 |

姿态由 autopilot 按威胁评估逐轮重算（§6.2）；手动模式=ATK（传统行为）。
**攻/防乘区不对称是刻意的**（1.3×0.9=1.17 攻优）：放置游戏节奏优先，压制姿态必须能终结战斗（C 门"轮数∈[4,30]"）。

## 3. 数值体系与战斗策略博弈

### 3.1 军备竞赛（三条曲线的对位）

| 曲线 | 公式 | 形状 | 设计意图 |
|---|---|---|---|
| 玩家力量 | §2.1 乘区堆叠 | 随培养阶梯上升（线性基座×乘区） | 培养有感知 |
| 怪 HP | `(6+4f)(10+f/3)/10`，boss ×3，周目 ×(1+ng)（>6 软化） | **二次方**（墙的来源） | 深层墙推进 |
| 怪 ATK | `4 + f×0.8 + 12×ng`，上限 250 | 线性 | 压力随层数单调涨 |

对位关系：玩家守备靠护甲堆叠（可到 60+词缀+圣所），怪 ATK 线性爬——**守备软上限（§2.1）
是军备竞赛的裁判**：前 20 点守备全额有效（新档唯一防御），堆到深层按半价折算，
防止"守备 3 倍碾压 → 深层刮痧 10 几点"的塌方（v12.2 修复，骑士 F100 每轮 15%→22%）。

### 3.2 墙的存在性与放置弧线

- 墙=怪 HP 二次方追上玩家线性力量。满练度墙在 ~F85-95；badge 3 是愿景，不是 run60 可刷的存量。
- 下层回复 35% maxHP（DESC_HEAL）：允许"再下一层"的贪心，压住药水经济。
- 放置收益走离线账本曲线（v5 起，Pecorelle 对齐）；模拟钟把游戏时间换算成真实时间（benchmark F 首通 18h）。

### 3.3 博弈：姿态 vs 怪物行为（RPS）

- 怪重击（HEAVY）→ GRD ×0.4 反制；怪 buff（怒吼 +30% 攻，2 轮）→ 集火斩首；
- EVA 滑步换技能 CD，但全程零输出 → 有"用途桥"才允许滑（§6.2）；
- 玩家的 race 数学（`combat_clock`：r_die vs r_win）产生 margin，margin<0 且无道具 → all-in 攻。
- **博弈的门**：C 张力门（F40 锚点：轮数 4-30、耗血 ≥20%、连平推 ≤10）+ G4 操作价值门（放置 vs 全操作 ≥15%）。

## 4. 经济链路

### 4.1 收入端（金币/精华/碎片/齿轮）

| 来源 | 公式/规则 | 备注 |
|---|---|---|
| 通关奖励 | `3+floor+rng(5)`；boss +10+floor | 深层线性的主泵 |
| 宝箱 | 金 3+rng(8)；8% 烟遁（<3 才给）；8% 药水（<5）；F30+ 碎片 | 消耗品免费上限=保有量 |
| 宝箱怪 | 20% 概率（盗贼减半），×2/×3 金 | 盗贼挖矿特色 |
| 稀有悬赏 | +15/+25 金、齿轮、碎片 | 隐藏房/挑战房 |
| 选择卡 | 伤换 15 金 / 羽换 25 金 | 风险交易 |
| 精华 | 门 boss +3、稀有悬赏 +5 | 许愿池/圣所专用 |
| 碎片 | 门 boss +1、精英 25%、F30+ 箱 | 合成专用 |

### 4.2 消耗端（每个口都有设计意图）

| 消耗口 | 价格曲线 | 设计意图 | 门 |
|---|---|---|---|
| 锻造 | `10 + 3×tier + tier²/3`（tier=武+防之和；双件都升，先升短板） | 金币→战力主阀；二次方减速 | E 跑步机 |
| 合成 | 碎片 `5×(rar+1)` + 金 `40×(rar+1)` | 碎片门节奏（R1 跑3/R2 跑10/R3 跑25+） | F 长线 |
| 客栈 | 10g | 路费保底 | — |
| 货郎 | 烟遁 `15+floor`、药水 `20+floor` | **生存有价**（v12.1：烟遁不再免费） | — |
| 许愿池 | 精华 25 **+ 金币累进税** `50+30×(prst+ng)+gold/8`；没金=双倍精华 | 金币终极排水口：囤金几次抽干；穷人双倍精华保底，井永不堵 | v121_economy |
| 圣所 | 精华 `4×(3/2)^lv` 几何涨价 | 精华长期去向 | G5 |
| 转生 | 需 `ng ≥ 1+prst/4`，prst += ng | 周目引擎：把 badge 变成全局 +2%/级 | prestige_loop |

**金币生命周期（v12.1 修复的核心）**：金币 run-only（死亡清零、活着出迷宫保留）。
收入随层数线性涨，锻造二次方减速 + cap 后必须有去处——**许愿池累进税是唯一全局排水口**，
货郎消耗品是每跑的边际开销。诊断工具 `tools/diag_econ.c`（60 跑逐层采样）是经济体检仪。

### 4.3 消耗品经济

- 烟遁：货郎 15+floor；autopilot 保有量 3；宝箱免费补到 3（超过要花钱）。
- 药水：货郎 20+floor；保有量 1；宝箱补到 5。
- 羽毛：仅宝箱/选择卡（回城稀缺资源，不卖）。
- **烟遁=房间内存活脱离**（回城、保留金币、explored 进度清）；技能版（盗贼 SK_SMOKEOUT）是战斗内脱离。
- 使用纪律见 §6.1 优先级——由真实伤害估算驱动（v12.2）。

## 5. 迷宫与回程

### 5.1 层与门

- F1-100 一座塔；F100 清 = badge（ng+1，回 F1，怪 HP ×(1+ng)、ATK +12/ng）。
- 门 boss：F25/50/75/100，过门 +3 精华 + 碎片；F25/50/75 有 15% 概率藏**太古 boss**（codex 收集）。
- 下层回复 35% HP（贪心阀门，§3.2）。
- 领域分布（`theme_kind`）：F1-20 荒原兽群 → F21-40 洞窟亡灵 → F41-60 火窟飞行 → F61-80 冰原兽群 → F81+ 混合。

### 5.2 房间事件

| 事件 | 概率/规则 | 旋钮 |
|---|---|---|
| 宝箱怪 | 箱子的 20%（盗贼减半） | MIMIC_CHANCE |
| 稀有怪 | 常规房 100ppm（F≥15 才出） | RARE_PPM |
| 挑战房 | 选择卡入口，富奖励 | — |
| 星陨 | 每步 4ppm 环境事件 | STARFALL_PPM |

## 6. AI 策略（OC 的自动驾驶）

### 6.1 战斗优先级（`dungeon_autopilot_battle`，每轮先于回合结算）

```
P1 收尾：  敌方总 HP ≤ pow×2 → 只管进攻（空分支=明确不防御）
P2 死线：  ehp ≤ enemy_threat_est() → 烟遁 > 药水（v12.2：读真实伤害！）
P3 逆风：  ehp < est×3 → 喝药稳线
P4 技能：  主职技 0 就绪 → 副职技 0 就绪
默认：     攻击（放置基线）
```

**`enemy_threat_est()` = blob_hit() 的期望值视角**（怒气、毒词缀、飞行齐射、姿态期望全含）。
这是 v12.2 的核心修复：AI 读"下一轮真实会掉的血"，不再读"原始攻击力总和"
（后者在深层高守备下虚高 5 倍，造成满血烟遁/残敌烟遁）。

### 6.2 姿态选择（`dungeon_stance_pick`，逐轮重算）

```
威胁 = assess_threat():        r_win×2≤r_die → 0 碾压
                              r_win≤r_die   → 1 赢但慢
                              r_die×2≥r_win → 2 输得慢
                              其他           → 3 快死了
姿态：threat 0→ATK；1→本命姿态（带用途桥：GRD 要 8 轮内收工、EVA 要技能桥）；
     2→GRD；3→EVA
护栏：GRD 预计 >10 轮 → ATK（反马拉松）；round>100 → ATK；all-in 条件 → ATK
```

### 6.3 编制与自动化

- auto_job：主职升级 → 旧主职滑入副槽（永不出现双同职）。
- 门 boss 自动换骑士带队（无 CD 惩罚，手动切换仍赢）。
- 探索自动化：camp（休息/锻造/补给）；城镇自动化：客栈→锻造（先短板）→补给→合成→转生→圣所→许愿池循环。
- **训练（auto-play）即游戏**：benchmark/balance_sim 的 driver 与设备 autopilot 是同一套模型调用，
  harness 与 device 行为不许可分叉（分叉即 bug——烟遁史证明了两次）。
